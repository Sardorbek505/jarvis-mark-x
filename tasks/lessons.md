# Уроки

## Безопасность
- Никогда не коммить файлы с реальными ключами. `config/api_keys.json` уже в `.gitignore` — но был добавлен в индекс ДО игнора. Всегда проверять `git ls-files` на наличие секретных файлов, даже если они в `.gitignore`.
- Не хардкодить CLIENT_ID/SECRET/TOKEN в `.py`-скриптах. Читать из config/env.
- Если секрет уже попал в историю git — игнора недостаточно, ключ нужно отозвать/перевыпустить.

## Структура репозитория
- Записи с режимом `160000` в `git ls-files -s` — это submodule-gitlinks. Без `.gitmodules` это битые ссылки/мусор.
- Одноразовые миграционные скрипты с абсолютными путями (`D:/...`) — удалять после применения.

## Windows: cp1251 роняет код в самый неподходящий момент
Консоль Windows по умолчанию cp1251. Любой `print()` с эмодзи (`✅`, `⚠️`) или
псевдографикой (`╔═╗`) падает с `UnicodeEncodeError`. Русский текст, тире и
многоточие — кодируются нормально, проблема только в символах вне cp1251.

Дважды за одну сессию это ударило именно по коду обработки ошибок:
`core/storage.py:safe_read_json` — код аварийного восстановления — печатал
`⚠️` и падал, роняя Джарвиса на битом конфиге вместо мягкого отката.

**Правило:** в пользовательский вывод — только ASCII-оформление (`[OK]`, `[!]`,
`===`), а лучше logger вместо print. Проверять под строгой консолью:
`sys.stdout = io.TextIOWrapper(io.BytesIO(), encoding="cp1251", errors="strict")`.

## Логгеры называются по-разному — массовые правки ломаются об это
В `actions/`, `core/`, `ui.py` логгер — `_logger`, в `telegram_bot/` — `logger`.
Скрипт массовой правки вписал везде `_logger` → `NameError` в 6 файлах, причём
падало бы ровно в момент поимки ошибки. Перед массовой заменой — проверять
фактическое имя в каждом файле:
`grep -E "^\s*\w+\s*=\s*logging\.getLogger"`.

## Тесты: `PermissionError` — это не про код
Симптом: все тесты падают с `PermissionError: [WinError 5]` на
`%LOCALAPPDATA%\Temp\pytest-of-User`. Причина не в проекте — сломан ACL самой
временной папки pytest (остаток от запуска из-под администратора). Признак:
даже `icacls`/`Get-Acl` не могут прочитать права.

Лечение (PowerShell от админа, синтаксис именно PowerShell — не `cmd`):
`Remove-Item -LiteralPath "C:\Users\User\AppData\Local\Temp\pytest-of-User" -Force -Recurse`
Pytest пересоздаст папку сам с правильным владельцем.

**Не лечить через `--basetemp` в `pytest.ini`:** pytest очищает эту папку при
каждом старте — фиксированный путь в конфиге это мина, а не решение.

## Молчаливые ошибки — главный источник долгоживущих багов
Было 60 обработчиков `except Exception: pass`. Из-за них баг «напоминание не
называет время» прожил месяцы: код не падал, а тихо ничего не делал.
При добавлении логов поток управления не менять — только видимость.
Уровень: `warning` для конфигов/состояния (тихий откат на дефолты = баг),
`debug` для цепочек фолбэков (иначе шум на каждом кадре).
В сообщение НЕ зашивать номер строки — `exc_info=True` даёт точную строку сам.
