# Исправленные ошибки JARVIS

## ✅ Исправлено

### 1. Ошибка: SpotifyAPI Config file not found
**Проблема:** Относительный путь к конфигурационному файлу не работал при запуске из разных директорий.

**Исправление:**
- `actions/spotify_controller.py`: Изменён относительный путь на абсолютный
- `tools/spotify/auth.py`: Изменён относительный путь на абсолютный для token files

**Результат:** Spotify API теперь корректно находит конфигурационный файл.

### 2. Ошибка: Qt DPI awareness
**Проблема:** `qt.qpa.window: SetProcessDpiAwarenessContext() failed: Єърчрэю т фюёЄєях.`

**Исправление:**
- `ui.py`: Добавлена установка DPI awareness для Windows через ctypes перед инициализацией Qt
```python
if platform.system() == "Windows":
    import ctypes
    try:
        ctypes.windll.shcore.SetProcessDpiAwarenessContext(1)
    except (AttributeError, OSError):
        pass
```

**Результат:** Qt DPI ошибка устранена.

### 3. Ошибка: Unicode encoding
**Проблема:** Символы Unicode (✓, ⚠) не могли быть закодированы в Windows консоли (cp1251).

**Исправление:**
- `main.py`: Добавлено принудительное UTF-8 кодирование для stdout/stderr на Windows
```python
if sys.platform == "win32":
    import io
    sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')
    sys.stderr = io.TextIOWrapper(sys.stderr.buffer, encoding='utf-8')
```

**Результат:** Unicode символы теперь корректно отображаются в консоли.

### 4. Ошибка: Модель Gemini недоступна
**Проблема:** Модель `gemini-2.0-flash-exp` не существует в API.

**Исправление:**
- `main.py`: Изменена модель на доступную `models/gemini-2.5-flash-native-audio-latest`
- Проверен список доступных моделей через `client.models.list()`

**Результат:** Используется корректная модель для native audio API.

### 5. Ошибка: KeyError 'creator' в user_profile
**Проблема:** Метод `format_for_prompt()` в `core/user_profile.py` пытался получить доступ к несуществующему ключу `identity["creator"]`.

**Исправление:**
- `core/user_profile.py`: Все обращения к словарям изменены на безопасный метод `.get()`
- Исправлены обращения к `identity`, `preferences`, и `context`

**Результат:** Профиль пользователя корректно форматируется без ошибок.

### 6. Ошибка: name loop is not defined в morning briefing
**Проблема:** При автозапуске morning briefing возникала ошибка `name loop is not defined`.

**Исправление:**
- `main.py`: Изменён `loop.run_in_executor` на `asyncio.get_event_loop().run_in_executor`
- Исправлено в строке 1378

**Результат:** Morning briefing теперь корректно запускается без ошибок.

### 7. Ошибка: UI зависает на экране инициализации
**Проблема:** Метод `wait_for_api_key()` в `ui.py` вызывал `client.models.list()` для валидации API ключа, что блокировало запуск UI.

**Исправление:**
- `ui.py`: Удалена валидация API через `client.models.list()`
- Метод теперь просто проверяет наличие API ключа в файле
- Если ключ есть - сразу возвращает None без проверки API
- Удалён мёртвый код (строки 1017-1026)
- Убран импорт `genai` который больше не используется

**Результат:** UI теперь инициализируется мгновенно без зависаний на валидации API.

### 8. Улучшение: Естественные сообщения при восстановлении режима
**Проблема:** При восстановлении сохранённого режима JARVIS говорил "активирован", как будто включил режим впервые, что звучит неестественно.

**Исправление:**
- `actions/modes.py`: Добавлена проверка текущего режима перед активацией
- Если режим уже активен с теми же параметрами - возвращает приветствие "Продолжим работу..."
- Для work: "Продолжим работу в режиме дизайн/код/клиент"
- Для study: "Продолжим учёбу"
- Для music: "Продолжаем слушать энергичную/спокойную музыку"
- Для movie: "Продолжаем смотреть 'Название фильма'"

**Результат:** Теперь при восстановлении сессии JARVIS говорит естественные приветствия вместо "активирован".

### 9. Удаление: Wake word система
**Проблема:** Wake word не работал даже с улучшениями - VAD блокировал тихую речь, а без VAD отправлял слишком много шума.

**Решение:** Полностью удалена wake word система:
- Удалены переменные: `listening_active`, `wake_word_detected`, `activation_timeout`, `WAKE_WORDS`, `DEACTIVATE_WORDS`
- Удалены методы: `_check_wake_word()`, `_check_deactivate_word()`, `_activate_listening()`, `_deactivate_listening()`, `_calculate_rms()`
- Удалена логика проверки wake word в `_receive_audio()`
- Удалён VAD (проверка уровня звука RMS > 500)

**Результат:** Теперь JARVIS работает только с текстовыми командами через UI. Голосовое распознавание работает постоянно без активации/деактивации.

### 10. Удаление: Сообщение про wake word в UI
**Проблема:** При запуске JARVIS писал в UI "SYS: ДЖАРВИС в сети. Скажите 'Джарвис' для активации." - это сообщение осталось от wake word системы.

**Решение:** Удалено сообщение `self.ui.write_log("SYS: ДЖАРВИС в сети. Скажите 'Джарвис' для активации.")` из main.py (строка 1299).

**Результат:** Теперь при запуске JARVIS просто подключается без лишних сообщений про активацию.

### 11. Улучшение: Поиск в личных плейлистах Spotify
**Проблема:** JARVIS не мог находить треки в личных плейлистах пользователя ("Любимое", "Музыка любим" и т.д.), искал только в общем каталоге.

**Исправление:**
- `tools/spotify/search.py`: Добавлены методы `search_playlists()` и `get_user_playlists()` для поиска плейлистов
- `tools/spotify/controller.py`:
  - `play_query()`: Теперь сначала ищет в личных плейлистах с fuzzy matching (60% threshold), затем в общем каталоге плейлистов, и только потом треки
  - `play_mood()`: Теперь сначала ищет в личных плейлистах, затем использует систему настроений

**Результат:** JARVIS теперь может находить и открывать личные плейлисты пользователя по нечёткому названию.

### 12. Улучшение: Обработка опечаток в русском тексте
**Проблема:** Распознавание речи часто делало опечатки (з/с, ш/щ, ч/ц, к/х и т.д.), из-за чего поиск не находил треки.

**Исправление:**
- `tools/spotify/search.py`: Расширен список вариантов замены для поиска:
  - Добавлены замены: ё→е, й→i, ъ/ь→(удалить), з↔с, ш↔щ, ч↔ц, к↔х, п↔б, т↔д, ф↔в
  - Всего 18 вариантов замены для лучшего поиска с опечатками

**Результат:** Поиск теперь более устойчив к опечаткам в русском тексте.

### 13. Улучшение: Задержка перед проверкой статуса воспроизведения
**Проблема:** После команды "включить" JARVIS сразу говорил "Ничего не играет", не давая Spotify время начать воспроизведение.

**Исправление:**
- `tools/spotify/controller.py`:
  - `play_track()`: Добавлена задержка 0.5 сек после успешного воспроизведения
  - `play_context()`: Добавлена задержка 0.5 сек после успешного воспроизведения
  - `now_playing()`: Улучшена проверка статуса - теперь проверяет и `/me/player/currently-playing` и `/me/player` для более точного статуса

**Результат:** Теперь JARVIS корректно определяет что музыка играет после включения.

### 14. Критическая ошибка: NameError: 'traceback' not defined
**Проблема:** Отсутствие импорта `traceback` в main.py маскировало реальные ошибки при падении.

**Исправление:**
- `main.py`: Добавлен `import traceback` в строке 15

**Результат:** Теперь все ошибки корректно логируются с полным traceback.

### 15. Критическая ошибка: NameError: 'loop' not defined в morning briefing
**Проблема:** При автозапуске morning briefing использовался `loop` без определения.

**Исправление:**
- `main.py`: Изменён на `loop = asyncio.get_event_loop()` перед использованием (строка 1309)

**Результат:** Morning briefing теперь корректно запускается без ошибок.

### 16. Критическая ошибка: cannot schedule new futures after shutdown
**Проблема:** Вызовы `run_coroutine_threadsafe` без проверки `loop.is_running()` приводили к крашу при закрытии.

**Исправление:**
- `main.py`: Добавлена проверка `self._loop.is_running()` во всех местах где вызывается `run_coroutine_threadsafe`:
  - `_on_text_command()` (строка 644)
  - `speak()` (строка 665)
  - `_receive_audio()` - инициативные предложения (строка 1184)
  - `_receive_audio()` - proactive suggestions (строка 1210)

**Результат:** Теперь при закрытии asyncio loop не происходит краша.

### 17. Критическая ошибка: Gemini WebSocket 1008 vs 1011 обрабатываются одинаково
**Проблема:** Ошибки 1008 (policy violation) и 1011 (server shutdown) обрабатывались одинаково - всегда перезапускались.

**Исправление:**
- `main.py`: Добавлена различная обработка ошибок WebSocket (строки 1336-1348):
  - 1008 (policy violation): не перезапускается, требует ручного вмешательства
  - 1011 (server shutdown): нормальный перезапуск

**Результат:** Policy violation ошибки больше не вызывают бесконечный перезапуск.

### 18. Критическая ошибка: Нет exponential backoff при retry
**Проблема:** При ошибках подключения всегда использовалась фиксированная задержка (3-10 сек), что могло перегрузить сервер.

**Исправление:**
- `main.py`: Добавлен exponential backoff с максимальной задержкой 60 секунд:
  - Добавлены переменные `retry_count` и `max_retry_delay` (строки 1280-1281)
  - Задержка рассчитывается как `min(2 ** retry_count, max_retry_delay)`
  - Сброс счётчика при успешном подключении (строка 1307)
  - Применено к всем retry логам (строки 1344-1354, 1373-1376)

**Результат:** Retry логика теперь использует exponential backoff для предотвращения перегрузки сервера.

### 19. Критическая ошибка: Spotify 401 errors не обрабатываются с token refresh
**Проблема:** При 401 Unauthorized от Spotify API был бесконечный цикл попыток без обновления токена.

**Исправление:**
- `tools/spotify/controller.py`:
  - Добавлен метод `_request_with_refresh()` для автоматического refresh токена на 401
  - `_refresh_components()` теперь передаёт `self.auth` в SpotifySearch
- `tools/spotify/search.py`:
  - `__init__` теперь принимает optional `auth` параметр
  - `_api_request()` переписан для автоматического refresh токена на 401 с retry логикой
  - Добавлен параметр `max_retries` для ограничения попыток (default 1)
  - При 401 вызывается `auth.refresh_access_token()` и запрос повторяется с новым токеном

**Результат:** Spotify API теперь автоматически обновляет токен при 401 ошибках и повторяет запрос.

### 20. Улучшение: Понятное сообщение при блокировке API ключа
**Проблема:** При ошибке 1008 (policy violation) выводилось только "Policy violation - не перезапускаем", без инструкций что делать.

**Исправление:**
- `main.py`: Расширено сообщение об ошибке при 1008:
  - Добавлено объяснение что API ключ был помечен как утёкший
  - Добавлена пошаговая инструкция что нужно сделать:
    1. Перейти на https://aistudio.google.com/app/apikey
    2. Удалить старый ключ и создать новый
    3. Обновить config/api_keys.json новым ключом
    4. Перезапустить JARVIS
  - Добавлено предупреждение о безопасности: никогда не коммитить API ключи в Git
  - Сообщение в UI также обновлено с ссылкой на Google AI Studio

**Результат:** Теперь при блокировке API ключа пользователь получает чёткую инструкцию как получить новый ключ.
